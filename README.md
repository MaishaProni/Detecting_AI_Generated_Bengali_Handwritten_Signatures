# Detecting AI-Generated Bengali Handwritten Signatures Using Deep Learning

> **A cross-generator deep-learning study for detecting AI-generated Bengali handwritten signatures.**

This project investigates whether a Bengali handwritten signature was produced by a **human** or generated by an **AI image-generation system**. The study introduces a writer-disjoint benchmark dataset and evaluates three CNN-based approaches under both **in-distribution** and **cross-generator** settings.

The work is described in the paper:

**Detecting AI-Generated Bengali Handwritten Signatures Using Deep Learning: A Cross-Generator Evaluation**

---

##  Project Overview

Generative AI systems can now create handwriting-like images that can look similar to genuine handwritten signatures. This creates a new challenge for document authentication.

Unlike conventional signature verification, which asks:

> **"Does this signature belong to the claimed writer?"**

this project asks:

> **"Was this signature written by a human or generated by an AI system?"**

The project focuses specifically on **Bengali handwritten signatures**, an area that has received comparatively limited attention in AI-generated-content detection research.

### Main objectives

- Build a benchmark dataset containing genuine and AI-generated Bengali signatures.
- Detect AI-generated signatures using deep-learning models.
- Compare different CNN architectures.
- Evaluate detection performance separately for different AI generators.
- Test whether models generalize to an **unseen AI generator**.
- Compare domain-specific CNN models with publicly available general-purpose AI-image detectors.

---

## ✨ Key Contributions

1. **Bengali AI-generated signature detection**

   We study the distinction between genuine Bengali handwritten signatures and signatures generated by modern AI systems.

2. **Multi-generator benchmark**

   The benchmark contains genuine signatures and AI-generated signatures produced using:

   - Google Gemini
   - Qwen
   - ChatGPT

3. **Writer-disjoint evaluation**

   Genuine, Gemini, and Qwen samples associated with the same writer are kept within the same partition to reduce writer leakage.

4. **Generator-wise evaluation**

   Performance is reported separately for Gemini, Qwen, and ChatGPT generated signatures.

5. **Cross-generator evaluation**

   A complete generator is withheld during training and used as an unseen test domain.

6. **External detector comparison**

   Two publicly available AI-image detectors are evaluated on a separate set of Bengali signature images.

#  Dataset

The final benchmark contains:

| Source | Raw Images | After Deduplication |
|---|---:|---:|
| Genuine — BHSig260 Bengali | 1,140 | 993 |
| Gemini — reference-based | 561 | 543 |
| Qwen — reference-based | 300 | 300 |
| ChatGPT — no-reference | 198 | 198 |
| **Total** | **2,199** | **2,034** |

### Genuine signatures

The genuine signatures are obtained from the Bengali portion of the **BHSig260** dataset.

- 100 writers
- 10–12 samples per writer
- Writer identity retained for writer-level partitioning
- Exact duplicates removed using MD5 hashing
- 993 unique genuine signatures after deduplication

### AI-generated signatures

#### Gemini

Reference-based generation was used. Genuine signature images were provided as references and Gemini was prompted to generate visually similar Bengali signatures.

- 543 images after deduplication
- 54 writer-linked folders

#### Qwen

Qwen was also evaluated using a reference-based generation procedure.

- 300 images
- 25 writer-linked folders

#### ChatGPT

ChatGPT samples were generated using **text prompts containing common Bengali names**, without providing genuine signature images as references.

- 198 images
- No associated writer identity

# 🧹 Preprocessing

The project applies a unified preprocessing pipeline to reduce unwanted source-dependent shortcuts.

### 1. Color normalization

Original genuine and AI-generated images used different color modes.

All images are converted to:

```text
RGB
```

### 2. Margin cropping

Excess white margins are detected and cropped using an adaptive brightness threshold while retaining padding around the signature.

### 3. Background normalization

Border-region brightness is normalized toward white to reduce differences caused by generator-specific backgrounds.

### 4. Aspect-ratio preserving resize

Images are resized while preserving their aspect ratio.

The longer side is scaled to:

```text
224 pixels
```

Images are then white-padded to:

```text
224 × 224
```

### 5. Normalization

Training-set normalization statistics:

```text
Mean = (0.971, 0.971, 0.971)
Std  = (0.147, 0.147, 0.147)
```

### 6. Data augmentation

Augmentation is applied only to the training set:

- Rotation: ±5°
- Translation: ±3%
- Scaling: 97–103%
- Brightness variation: ±10%
- Contrast variation: ±10%

Horizontal and vertical flips are avoided because they can distort the natural structure of signatures.

#  Dataset Partitioning

The reference-based Gemini and Qwen samples are linked to genuine writers.

Therefore, all genuine, Gemini, and Qwen samples belonging to the same writer remain in the same partition.

The writer groups are divided into:

```text
70% Training
15% Validation
15% Test
```

ChatGPT images do not have writer identities, so they are split independently at the image level using the same ratio.

### Final split

| Split | Images |
|---|---:|
| Training | 1,461 |
| Validation | 308 |
| Test | 265 |

The final test set contains:

| Source | Test Images |
|---|---:|
| Genuine | 149 |
| Gemini | 27 |
| Qwen | 60 |
| ChatGPT | 29 |
| **Total** | **265** |

The test set is kept isolated during model development and is used only for final evaluation.

#  Models

Three CNN architectures are evaluated.

## 1. Custom CNN

A lightweight CNN is trained from scratch.

Architecture:

```text
Input: 224 × 224 × 3

Conv Block 1
32 filters
GroupNorm
ReLU
MaxPool

Conv Block 2
64 filters
GroupNorm
ReLU
MaxPool

Conv Block 3
128 filters
GroupNorm
ReLU
MaxPool

Conv Block 4
256 filters
GroupNorm
ReLU
MaxPool

Global Average Pooling

256 → 64
ReLU
Dropout 0.3

64 → 2
Dropout 0.2

Softmax
```

The four convolutional blocks reduce the spatial representation to:

```text
14 × 14 × 256
```

before global average pooling.

## 2. ResNet18

ResNet18 is initialized with ImageNet-pretrained weights.

Training uses:

1. Frozen backbone training
2. Classification-layer replacement
3. Backbone unfreezing
4. Fine-tuning with a smaller learning rate

## 3. EfficientNet-B0

EfficientNet-B0 is also initialized with ImageNet-pretrained weights and fine-tuned using the same general transfer-learning strategy.

- **PyTorch**

- Early stopping
- Learning-rate reduction on validation-loss plateau

### Learning rates

#### Custom CNN

```text
3 × 10⁻⁴
```

#### ResNet18 / EfficientNet-B0

Initial training:

```text
1 × 10⁻³
```

Fine-tuning:

```text
1 × 10⁻⁵
```

The pretrained backbone is unfrozen after epoch 10.

### Training callbacks

```text
Early stopping patience = 7
LR reduction factor = 5
LR plateau patience = 2
```

# 📈 Results

## Overall Test Performance

The final test set contains **265 images**.

| Model | Accuracy | Precision | Recall | F1 | ROC-AUC | Human Recall | AI Recall |
|---|---:|---:|---:|---:|---:|---:|---:|
| **Custom CNN** | **96.98%** | **98.21%** | 94.83% | **96.49%** | **0.997** | **98.66%** | 94.83% |
| ResNet18 | 93.21% | 86.57% | **100.00%** | 92.80% | 0.998 | 87.92% | **100.00%** |
| EfficientNet-B0 | 90.57% | 83.21% | 98.28% | 90.12% | 0.984 | 84.56% | 98.28% |

The custom CNN correctly accepted **147/149 genuine signatures** and correctly detected **110/116 AI-generated signatures**.

ResNet18 and EfficientNet-B0 achieve higher AI recall but produce more false positives on genuine signatures. Therefore, accuracy alone does not fully describe detector behavior.

### Custom CNN

| Human vs. ChatGPT | 98.88% | 93.55% | 100.00% | 0.9667 | 1.000 |

Gemini-generated signatures are substantially harder to detect than Qwen and ChatGPT samples in this benchmark.

# 🌐 Cross-Generator Generalization

A key experiment evaluates whether a model can detect an AI generator that it has **never seen during training**.

ResNet18 is trained using two generators and tested on the third.

| Held-Out Generator | Trained On | Accuracy | AI Recall | F1 | AUC | Human Recall |
|---|---|---:|---:|---:|---:|---:|
| ChatGPT | Human + Gemini + Qwen | 69.66% | 27.59% | 0.2286 | 0.567 | 77.85% |
| Gemini | Human + ChatGPT + Qwen | 84.09% | 3.70% | 0.0667 | 0.738 | 98.66% |
| Qwen | Human + ChatGPT + Gemini | 66.03% | 98.33% | 0.6243 | 0.959 | 53.02% |

These results demonstrate a major gap between **in-distribution performance** and **unseen-generator generalization**.

In particular, the Gemini hold-out experiment produces only **3.7% AI recall**, while the ChatGPT hold-out experiment produces an AUC close to chance.

The external detectors show highly uneven behavior across generators, indicating that general-purpose AI-image detection does not reliably transfer to Bengali handwritten signatures.

#  Evaluation Protocol

The project evaluates models from three complementary perspectives.

### 1. Overall classification

The complete held-out test set is used to measure:

- Accuracy
- Precision
- Recall
- F1-score
- ROC-AUC
- Human recall
- AI recall

### 2. Generator-wise evaluation

The test set is separated into:

```text
Human + Gemini
Human + Qwen
Human + ChatGPT
```

This identifies which generation sources are easier or harder to detect.

### 3. Cross-generator evaluation

One complete generator is removed from training and used as an unseen test domain.

This measures whether the model learns:

```text
general synthetic-signature characteristics
```

or becomes dependent on:

```text
generator-specific artifacts
```

#  Important Findings

The experiments indicate several important observations:

- A lightweight custom CNN can achieve strong in-distribution performance on this benchmark.
- AI-generated signatures from different generators have substantially different detection difficulty.
- Gemini-generated signatures are more difficult to detect in the reported experiments.
- High in-distribution accuracy does **not** guarantee generalization to an unseen generator.
- Cross-generator performance can degrade substantially.
- General-purpose AI-image detectors show inconsistent performance on Bengali handwritten signatures.
- Evaluation using only aggregate accuracy can hide important differences between false positives on genuine signatures and missed AI-generated signatures.

# ⚠️ Limitations

The current benchmark has several limitations:

- Only three AI generators are evaluated.
- The genuine dataset contains 100 writers.
- ChatGPT-generated signatures do not have writer identities.
- Cross-generator experiments are limited to the available generators.
- The current evaluation mainly uses digital images rather than real print-scan or camera-captured documents.
- AI generators and their models may change over time.
- Strong in-distribution results should not be interpreted as universal AI-generated-signature detection capability.
